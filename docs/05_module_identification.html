5  Module Identification

This chapter describes Step 4 of the FeatureMAP pipeline: identifying functional modules from the PCSF-derived subnetwork using identify_module().

Important

Prerequisites: You need a featuremap_result object from Subnetwork Extraction, with stage "subnetwork_extracted".

5.1 What identify_module() Does

identify_module() performs community detection on the extracted subnetwork and then evaluates module significance using permutation testing.

At a high level, this step performs the following operations:

  1. Construct a module detection graph: A metabolite-only subgraph is derived from the PCSF subnetwork. Steiner nodes with low occurrence frequency can be filtered using node_freq.

  2. Detect network communities: Community detection algorithms are applied to partition the network into candidate modules.

  3. Build module membership table: Node-to-module assignments are recorded in module_table.

  4. Compute module activity scores: Module scores summarize the statistical signal from features mapped to metabolites within the module.

  5. Assess statistical significance: A permutation procedure is used to estimate empirical significance and control false discovery rate.

This step converts the extracted metabolic network into functional modules supported by both network topology and feature-level statistical evidence.

5.2 Key Parameters

Parameter Default Description
res required featuremap_result returned by extract_subnetwork()
method "louvain" Community detection algorithm
min_size 3 Minimum module size retained
max_size 100000 Maximum module size retained
n_perm 100 Number of permutations for significance testing
seed 123 Random seed for reproducibility
workers 4 Parallel workers for permutation testing
node_freq 0.05 Frequency threshold for retaining Steiner nodes
louvain_resolution 1 Resolution parameter for Louvain clustering
walktrap_steps 4 Number of steps used in walktrap clustering

5.3 Basic Usage

  • Louvain (default)
  • Leading Eigen
  • Fast Greedy
  • Walktrap
res <- identify_module(
  res = res,
  method = "louvain",
  min_size = 3,
  max_size = 100000,
  n_perm = 100,
  seed = 123,
  workers = 4,
  node_freq = 0.05,
  louvain_resolution = 1
)
res <- identify_module(
  res = res,
  method = "leading_eigen",
  min_size = 3,
  max_size = 100000,
  n_perm = 100,
  seed = 123,
  workers = 4,
  node_freq = 0.05
)
res <- identify_module(
  res = res,
  method = "fast_greedy",
  min_size = 3,
  max_size = 100000,
  n_perm = 100,
  seed = 123,
  workers = 4,
  node_freq = 0.05
)
res <- identify_module(
  res = res,
  method = "walktrap",
  min_size = 3,
  max_size = 100000,
  n_perm = 100,
  seed = 123,
  workers = 4,
  node_freq = 0.05,
  walktrap_steps = 4
)

5.4 Clustering Methods

  • louvain
    A fast modularity optimization algorithm that iteratively merges nodes and communities to maximize network modularity. It is widely used for large biological networks.

  • leading_eigen
    A spectral method that partitions the network based on the leading eigenvectors of the modularity matrix. It identifies communities by separating nodes according to their contribution to modularity.

  • fast_greedy
    An agglomerative hierarchical clustering method that starts with each node as its own community and progressively merges communities to increase modularity.

  • walktrap
    A random-walk-based community detection algorithm that simulates short random walks on the network. The intuition is that random walks tend to remain within densely connected regions.

Different algorithms may produce slightly different module boundaries. Comparing multiple methods can help evaluate module robustness.

Note

Here, annotated metabolites are nodes directly linked to observed LC–MS features through the feature annotation step, whereas hidden metabolites are Steiner nodes introduced during PCSF optimization to connect annotated metabolites within the metabolic reaction network. Hidden metabolites are not directly supported by measured features, but may provide important network context.

5.5.2 Module significance table

module_score summarizes statistics for each detected module:

head(res$module_score)

#   Module Module_size Annotated_nodes Module_score           p       fdr
# 1      1         148             130    1.3944882 0.004536258 0.2177404
# 2     15          80              66    0.8717769 0.058164843 0.9960879
# 3     19          37              33    0.7624376 0.095688593 0.9960879
# 4     17          21              20    0.6974986 0.127492917 0.9960879
# 5     14          51              47    0.6885808 0.132541184 0.9960879
# 6      3          50              48    0.5985351 0.194456787 0.9960879

Important columns include:

  • Module – module identifier
  • Module_size – number of metabolite nodes in the module
  • Annotated_nodes – number of nodes supported by feature annotations
  • Module_score – aggregated activity score of the module
  • p – permutation-based p-value
  • fdr – multiple-testing corrected p-value

Modules with lower p or fdr values indicate stronger statistical support and are typically prioritized for downstream biological interpretation.

Tip

If too many tiny modules appear, increase min_size or tighten node_freq. If modules are too coarse, try alternative methods or relax these cutoffs.
