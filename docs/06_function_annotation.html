6  Function Annotation

This chapter describes Step 5 of the FeatureMAP pipeline: annotating statistically supported modules with annotate_module().

Important

Prerequisites: Complete module identification with identify_module()and Make sure your res object is already at stage "module_identified".

6.1 What annotate_module() Does

annotate_module() performs module-level biological interpretation for statistically supported modules in Step 4.

This step integrates three sources of information:

  1. Metabolite annotation summary: Metabolites contained in each significant module are summarized using the selected reference namespace (kegg or hmdb).

  2. Optional literature retrieval: Relevant PubMed articles are retrieved and ranked for the top metabolites in each module.

  3. LLM-based interpretation: A language model synthesizes module-level interpretations including title, summary, confidence label, and reasoning.

Only modules passing the significance cutoff (p or fdr) are annotated. This step converts statistically identified network modules into interpretable biological hypotheses.

6.2 Key Parameters

Parameter Default Description
res required featuremap_result returned by identify_module()
p "fdr" Column in res$module_score used for filtering
pcutoff 0.05 Threshold applied to the selected significance column
ref_data NULL Optional functional reference annotation table
species "human" Species context used in module interpretation
biospecimen NULL Biospecimen context (e.g. plasma, serum, tissue)
phenotype NULL Disease or phenotype context
pubmed TRUE Whether to retrieve PubMed evidence
years 5 Time window for literature search
top_paper 3 Number of retained papers per metabolite
min_similarity 0.6 Embedding similarity cutoff used to filter literature
provider "openai" LLM and embedding provider. Currently supported options include "openai", "gemini", and "siliconflow"
embed_model "text-embedding-3-small" Embedding model used for literature ranking (model availability depends on the selected provider)
llm_model "gpt-4.1-mini" Language model used for module interpretation (model availability depends on the selected provider)
NCBI_api_key "" NCBI Entrez API key for PubMed
llm_api_key "" API key for the selected LLM provider
Note

If ref_data = NULL, FeatureMAP automatically loads the functional reference resource corresponding to the metabolite namespace used in earlier steps.

Tip

How to obtain an LLM API key

FeatureMAP currently supports "openai", "gemini", and "siliconflow" as LLM providers.
You can apply for an API key from the corresponding official platform:

  • OpenAI: https://platform.openai.com/
  • Gemini (Google AI Studio): https://ai.google.dev/aistudio
  • SiliconFlow: https://siliconflow.cn/
Tip

How to obtain a PubMed / NCBI API key

If you enable PubMed retrieval, you need to apply for an NCBI API key for higher request limits: https://account.ncbi.nlm.nih.gov/settings/

6.3 Basic Usage

  • Database + LLM only
  • Database + PubMed + LLM
res <- annotate_module(
  res = res,
  p = "fdr",
  pcutoff = 0.05,
  ref_data = NULL,
  species = "human",
  biospecimen = "plasma",
  phenotype = "disease phenotype",
  pubmed = FALSE,
  provider = "openai",
  llm_model = "gpt-4.1-mini",
  llm_api_key = "your llm api key"
)
res <- annotate_module(
  res = res,
  p = "fdr",
  pcutoff = 0.05,
  ref_data = NULL,
  species = "human",
  biospecimen = "plasma",
  phenotype = "disease phenotype",
  pubmed = TRUE,
  years = 5,
  top_paper = 3,
  min_similarity = 0.6,
  provider = "openai",
  embed_model = "text-embedding-3-small",
  llm_model = "gpt-4.1-mini",
  NCBI_api_key = "your ncbi api key",
  llm_api_key = "your llm api key"
)
Note
  • Provide species, biospecimen, and phenotype whenever possible
  • Use API keys from environment variables rather than hard-coding them

6.4.1 Module interpretation table

module_function contains the final module-level interpretation generated by the LLM. Important fields include:

  • module_id – the module ID identified by previous step
  • title – a concise functional label summarizing the dominant biological theme of the module
  • summary – a paragraph-level interpretation of the module based on metabolite composition, network context, and optional literature evidence
  • confidence_label – a qualitative confidence level for the interpretation
  • rationale – a short explanation of why the inferred function is biologically plausible in the specified study context
  • raw_response – the original LLM response retained for transparency

This table provides a concise interpretation of each statistically supported module.

6.4.2 Literature evidence table

When pubmed = TRUE, FeatureMAP also returns ranked PubMed evidence (module_top_metabolite_pmids) for top metabolites in each module.

  • Module and Module_label – the module being annotated
  • Compound_ID and Compound_name – the metabolite used for literature retrieval
  • PMID_rank – the rank of the selected paper for that metabolite
  • PMID – PubMed identifier
  • title – article title
  • score_embed – semantic relevance score used for literature ranking

Higher score_embed values indicate stronger semantic relevance between the literature and the module context.

6.5 Common Issues

  • PubMed retrieval is slow Start with fewer modules, a shorter years window, or pubmed = FALSE for validation.

  • No useful literature retained Relax min_similarity, increase years, or provide a more specific phenotype.

  • Provider/model mismatch Make sure the selected provider, embed_model, and llm_model are compatible.

6.6 Practical Checks Before Running

head(res$module_score)
sum(res$module_score$fdr < 0.05, na.rm = TRUE)

If this count is zero, it is better to revisit Step 4 before trying module annotation.
