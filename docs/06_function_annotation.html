6  Function Annotation

This chapter describes Step 5 of the FeatureMAP pipeline: annotating statistically supported modules with annotate_module(), and, optionally, integrating the annotated modules into a study-level picture with synthesize_modules().

Important

Prerequisites: Complete module identification with identify_module() and make sure your res object is already at stage "module_identified".

6.1 What annotate_module() Does

annotate_module() performs module-level biological interpretation for the modules that passed the significance filter in Step 4.

Regardless of the mode you choose, the function always starts from the same deterministic evidence, computed in R rather than by the language model:

  1. Metabolite annotation: Metabolites of each significant module are annotated with class and pathway metadata from both HMDB and KEGG references.
  2. Top and anchor metabolite selection: Module members are ranked by 0.7 * Importance + 0.3 * Node_freq, and a Gaussian mixture model selects the leading metabolites that represent the module.
  3. Module-level statistics: Signal concentration, KEGG and HMDB pathway coverage, global direction of change, and the endogenous/exogenous origin profile are computed.

The interpretation itself is then produced by an LLM, in one of two modes.

6.1.1 Fast mode (mode = "fast")

A two-call pipeline, and the recommended default:

  1. LLM call 1 – from metabolite evidence only (no phenotype), the model returns hypothesis_type, title and functional_summary.
  2. Optional PubMed retrieval – the module title and each top metabolite are searched separately; the retained articles are deduplicated by PMID.
  3. LLM call 2 – with the study context and the literature, the model returns phenotype_relationship, confidence_label and rationale.

6.1.2 Advanced mode (mode = "advanced")

A multi-agent debate pipeline that produces one row per surviving hypothesis instead of one row per module:

  1. P0 Proposer – generates 1–3 candidate biochemical hypotheses from the metabolite evidence only.
  2. S1 Skeptic – challenges each hypothesis on biochemical, origin, species and biospecimen grounds, without seeing the phenotype or the literature.
  3. P1 Proposer revision – keeps, modifies or drops each hypothesis.
  4. S2 / P2 – a second debate round runs only if revisions were made or major challenges remained unanswered.
  5. Optional PubMed – anchor-metabolite and per-hypothesis title searches, retained for the arbiter only.
  6. A0 Arbiter – delivers a final accepted / rejected verdict per hypothesis, with a confidence score and a residual-ambiguity note.
  7. Optional synthesis – with synthesize = TRUE, accepted hypotheses from all modules are integrated across modules (see Section 6.6).
Tip

Use fast mode for routine analyses and for a first look at your data: it is markedly cheaper and faster. Use advanced mode when a module is ambiguous, when you want to see the reasoning that supports or rejects an interpretation, or when you want a study-level synthesis across modules.

Note

If ref_data = NULL, FeatureMAP automatically loads the cached HMDB and KEGG functional and pathway references.

Tip

How to obtain an LLM API key

  • OpenAI: https://platform.openai.com/
  • Gemini (Google AI Studio): https://ai.google.dev/aistudio
  • SiliconFlow: https://siliconflow.cn/

provider = "local" targets any OpenAI-compatible endpoint (for example a self-hosted vLLM server) and needs no key, only a base_url.

Tip

How to obtain a PubMed / NCBI API key

If you enable PubMed retrieval, apply for an NCBI API key for higher request limits: https://account.ncbi.nlm.nih.gov/settings/

Important

Which significance column should you use? p = "fdr" with pcutoff = 0.05 is the right default for a real study. On the demo dataset, however, no module reaches fdr < 0.05 and only one module passes the raw permutation p-value (see Module Identification). The examples below therefore use p = "p", so that the step actually has a module to annotate.

Always inspect res$module_score before this step, and state in your write-up which column you filtered on.

  • class_coverage – compound class composition per module
  • pathway_coverage$hmdb / pathway_coverage$kegg – pathway ID, name, coverage and number of hits per module
  • top_metabolites / anchor_metabolites – the metabolites shown to the model, with their ranks

6.5 Interactive HTML Reports

6.5.1 Debate traces

With debate_html = TRUE, advanced mode writes one chat-style page per module to html_dir, named debate_<module_id>.html. You can also re-export them later from a saved result, without calling the LLM again:

# all modules
export_debate_html(res = res_adv, html_dir = "featuremap_html")

# a single module
export_debate_html(res = res_adv, module_id = "M1", html_dir = "featuremap_html")

export_debate_html() is the recommended interface for saved annotation results. generate_debate_html() is a lower-level constructor that requires the complete debate payload for one module and is normally only needed in custom workflows.

Each page shows the Proposer, Skeptic and Arbiter turns in order, so you can follow exactly why a hypothesis was kept, revised or rejected.

6.5.2 Synthesis network

When synthesize = TRUE, an interactive network page synthesis_network.html is written to html_dir automatically. To re-export it from a saved result:

export_synthesis_network_html(
  res         = res_adv,
  html_dir    = "featuremap_html",
  output_file = "synthesis_network.html"
)

generate_synthesis_network_html() does the same from a bare res$module_synthesis list, which is useful when you keep only the synthesis object:

generate_synthesis_network_html(
  synthesis     = res_adv$module_synthesis,
  study_context = res_adv$study_context,
  output_dir    = "featuremap_html",
  output_file   = "synthesis_network.html"
)

6.6 Cross-Module Synthesis

synthesize_modules() takes the accepted hypotheses of all annotated modules and integrates them into one picture of the study. It is run automatically by annotate_module(mode = "advanced", synthesize = TRUE), and can also be called on its own, for example to re-run the synthesis with a stronger model:

res_adv <- synthesize_modules(
  res           = res_adv,
  study_context = list(
    species     = "human",
    biospecimen = "plasma",
    phenotype   = "your disease phenotype"
  ),
  provider    = "openai",
  llm_model   = "gpt-4.1",
  llm_api_key = Sys.getenv("OPENAI_API_KEY"),
  max_tokens  = 4000,
  temperature = 0
)
Important

synthesize_modules() requires advanced mode output. Fast mode produces one flat annotation per module and no hypothesis-level verdicts, so it cannot be synthesized this way. If study_context is NULL, it is taken from res$study_context.

If only one module has accepted hypotheses, the LLM call is skipped and res$module_synthesis is returned with the deterministic parts only.

Note

The demo dataset cannot illustrate this step. Cross-module synthesis only becomes meaningful when several modules carry accepted hypotheses. The demo data has a single significant module, so synthesize_modules() skips the LLM call and returns the deterministic parts only.

The outputs shown below are therefore taken from a larger real dataset with many annotated modules, and are reproduced here only to show the structure of res$module_synthesis. Do not expect to reproduce these values with the demo data.

The synthesis combines two very different kinds of links:

  • Biology links are proposed by the LLM from hypothesis titles and summaries only, and are deliberately sparse.
  • Biochemical links are computed in R from direct MRN edges between top metabolites and from pathway ID overlap, so they are fully deterministic.

Results are stored in res$module_synthesis:

names(res_adv$module_synthesis)
# [1] "nodes" "clusters" "biology_links" "biochemical_links"
#     "relationships_sparse" "relationships" "module_relationships"
#     "summary" "raw_response"

res_adv$module_synthesis$clusters
# Example output; synthesis is generated from accepted advanced-mode hypotheses.
# # A tibble: 1 x 3
#   cluster_id cluster_theme                node_ids
#   <chr>      <chr>                        <chr>
# 1 C1         Purine and energy metabolism "M4::H1; M12::H1"

res_adv$module_synthesis$module_relationships
# # A tibble: 1 x 11
#   module_id_1 module_id_2 has_biochemical_link has_biology_link relation_type ...
#   <chr>       <chr>       <lgl>                 <lgl>            <chr>         ...
# 1 M4          M12         TRUE                  FALSE            biochemical   ...

cat(res_adv$module_synthesis$summary)
# The accepted module hypotheses form a study-level pattern centered on purine
# metabolism and related energy-transfer chemistry. The biochemical links should
# be interpreted together with the original module scores and phenotype context.
  • nodes – one row per accepted hypothesis, with node_id ("<module_id>::<hypothesis_id>") and its assigned cluster
  • clusters – thematic clusters (cluster_id, cluster_theme, and semicolon-separated member node_ids)
  • biology_links / relationships_sparse – LLM-proposed cross-module relationships with rationales
  • biochemical_links – MRN-edge and pathway-overlap evidence between hypotheses
  • relationships – the merged relationship table used to draw the network
  • module_relationships – module-pair summary with biochemical/biology flags, relation evidence, and relation_type being biochemical, biology, both or none
  • summary – the narrative integrating clusters, cross-module links and the phenotype
  • raw_response – the original LLM response, kept for transparency

6.7 Practical Checks Before Running

head(res$module_score)
sum(res$module_score$fdr < 0.05, na.rm = TRUE)
sum(res$module_score$p < 0.05, na.rm = TRUE)

If no module passes your threshold, annotate_module() returns an empty module_function and warns you. Either relax the filter (p = "p" instead of "fdr") or revisit Step 4 before trying module annotation.

6.8 Common Issues

  • No module annotated. Nothing passed p/pcutoff. Switch to p = "p", raise pcutoff, or revisit the module identification settings.

  • PubMed retrieval is slow. Start with a shorter years window, fewer significant modules, or pubmed = FALSE while you validate the workflow.

  • Advanced mode is expensive. Each module costs several LLM calls. Validate the pipeline in fast mode first, then re-run the modules you care about in advanced mode.

  • synthesize = TRUE was ignored. Synthesis only runs in advanced mode; in fast mode a warning is emitted and the step is skipped.

  • Provider/model mismatch. Make sure llm_model exists for the selected provider, and remember that provider = "local" requires a non-empty base_url.

6.9 Next Step

Module annotation is the last step of the R-package workflow. res$module_function, res$module_evidence and res$module_synthesis, together with the exported HTML pages, contain everything you need for downstream reporting.
